# План ядра Pentagon-4096 для Karabas Go / Mini / Mini G

Цель: вся машина [Pentagon-4096](https://github.com/AleksandrDneprCity/Pentagon-4096) (AleksandrDneprCity, MainBoard 10.7.1, TopBoard 5.3.1) на платах Karabas (XC6SLX25, ISE 14.7). Главное — **все видеорежимы и все расширенные порты** с точностью до поведения оригинала.

Оригинал собран на мелкой логике (КР1531 / КР1533) и AVR, HDL нет, эмулятора этой машины нет (поиск 2026-11-19). Ядро пишем сами по README, схеме и списку ошибок схемы (`READMY_ERRORS.md`). Схема MainBoard в PNG (6204×4757) читается на полном разрешении, в PDF есть текст цепей.

## Решения пользователя (2026-11-19)

- Объём: вся машина, не только видео и порты.
- Настройки, которые в оригинале задаёт BIOS Setup, выносим в OSD.
- Лицензия: пользователь пишет автору; пока считаем, что открытый проект брать можно. До ответа репозиторий на GitHub не создаём без решения пользователя.

Частичные эталоны: Unreal Speccy / ZEsarUX / Fuse для Pentagon 128 / 1024 (тайминг кадра, INT, #7FFD, TR-DOS, +3), ATM Turbo 2+ (палитра #xxFF), Pentagon 1024SL (если раскладка #EFF7 оттуда — проверить в Ф0). Для режимов, которых нигде больше нет, эталон — своя модель на Python и тестовые программы (sjasmplus в `/opt/sjasmplus`).

## Плата

XC6SLX25: 15 032 LUT6, 30 064 FF, 52 RAMB16. SRAM 4 МБ (2M×16), SDRAM 32 МБ (на Mini rev G2 ~CS SDRAM на T3 — `mini-g2-sdram-cs`; Mini G-топ с SDRAM должен это учесть). Вход 50 МГц. Сначала Mini G, Go / Mini — в последней фазе.

## Порты (из README, сверить со схемой в Ф0)

| Порт | Назначение |
|---|---|
| #FE | бордюр, бипер, магнитофон, клавиатура; номер цвета палитры биты 0-2 |
| #F6 | бит 3 номера цвета палитры (D3 бордюра) |
| #xxFF | запись: палитра 12 бит (D0-D7 + A8, A9, A12-A15), при #FF37 бит 5; чтение: порт атрибутов (полная дешифрация) |
| #7FFD | 128K + D5 / D6 / D7 (расширение или защёлка D5, опция #FC37 бит 4) |
| #DFFD | D0-D2 (Профи-1024) |
| #1FFD | D4 / D7 (расширение), +3 (D0-D2) |
| #EFF7 | D0 16 colors, D1 512×192, D3 ОЗУ 0 вместо ПЗУ, D5 мультиколор 8×1, D6 384×304, D7 открыть часы и скрытые порты |
| #FC37 | память: EM0 / EM1 (схемы 0-6), D5 защёлка / расширение, загрузка в статическое ОЗУ, многозадачность, режим +3 |
| #FD37 | подмена страниц основного ПЗУ страницами статического ОЗУ (только чтение) |
| #FE37 | цвет текста 512 моно (IGRB), цвет в 512, FlashColor, автоматический GigaScreen, положение INT |
| #FF37 | ПЗУ BIOS выкл., защёлка Gluk, страница BIOS, запрет кэша, запись палитры, запись / стирание основного ПЗУ |
| #FB / #7B (чтение) | теневое ОЗУ (кэш) 16 / 32 КБ |
| #BFF7 / #DFF7 | CMOS |
| #1F, #3F, #5F, #7F, #FF (TR-DOS) | ВГ93 (с исправлением: A3 = 1, ошибка 1 схемы) |
| Nemo IDE | порты по схеме |
| 0x33 | DivIDE / GS (плата-адаптер) |
| Kempston, мышь, AY #FFFD / #BFFD, SoundDrive | по схеме |

В схеме есть цепи, которых нет в README: `P_3FFD`, `P_5FFD`, `P_7FFDS`, `P_PRNO` / `P_PRNI` / `PRNROM`, `CACHE_ON` / `MCACHE`, `P_JYKB`, `P_MOUSE`, `P_ON`. Ф0 разбирает каждый дешифратор `P_*` с учётом ошибок схемы.

Ловушка `IN A,(n)` / `OUT (n),A`: если из ОЗУ выбран код DB / D3, до следующего M1 память выше 128 КБ выключена, а #7FFD декодируется неполностью (A1, A15).

## Видеорежимы (из README, сверить со схемой в Ф0)

| Режим | Включение | Данные |
|---|---|---|
| Стандартный 256×192 | — | 4000 / 5800 |
| Мультиколор 8×1 | #EFF7 D5 | пиксели 4000, атрибуты 6000 |
| 512×192 моно | #EFF7 D1, #FE37 D4 = 0 | 4000 / 6000, цвет из #FE37 D0-D3 |
| 512×192 цветной 8×8 | #EFF7 D1, #FE37 D4 = 1 | 4000 + 5800, 6000 + 7800 |
| 512×192 мультиколор 8×1 | #EFF7 D1 + D5, #FE37 D4 = 1 | 4000 / 6000, атрибуты страницы 4 C000 / E000 |
| 16 colors | #EFF7 D0 | 4000, 6000, страница 4 C000, E000; 2 пикселя в байте |
| 384×304 без бордюра | #EFF7 D6 | раскладка в `video_modes.txt` (в README ещё «384×288») — по схеме |
| FlashColor | #FE37 D5 | бит 7 атрибута: смешение INK / PAPER вместо мигания |
| Аппаратный GigaScreen | #FE37 D6 | включается сам по программному переключению экранов, экраны через строку, инверсия через кадр |
| Палитра 4096 | #xxFF, #FF37 D5 | 16 цветов → 12 бит |

Экраны 5 / 7 и «страница 4» в режимах 4 МБ и многозадачности выбираются цепями `SCR*` (узел видеоадреса DD39-DD46).

### Ф1 — Mini G, Pentagon-128 (ветка f1-minig)

Верх платы на kg_* (`kg_mcu2`: OSD, USB-клавиатура, загрузка ROM из `.kg`), CPU, SRAM 4 МБ, ПЗУ в SDRAM (или BRAM на первое время), стандартное видео и бордюр, развёртка Pentagon, INT Pentagon / фирменный, турбо 3,5 / 7 / 14, #FE / #7FFD / #FF, AY, бипер, магнитофон, Kempston-джойстик, HDMI со звуком.
Цель: BASIC 128 / 48, игры с ленты, тесты тайминга Pentagon (сверка с Unreal / Fuse).

Сделано (2026-11-20, ветка f1-minig):
- Машина `rtl/p4096/p4096.v` без привязки к плате: z80-silicon на clk_bus 28 МГц с разрешениями 3,5 / 7 / 14 (такт 3,5 = 2 точки растра), #FE / #F6 (яркость бордюра адресом), #7FFD (защёлка D5, чтение #7FFD), #xxFF (последний атрибут, FF на бордюре и в TR-DOS), Kempston #1F, AY / TurboSound, переключение ПЗУ TR-DOS (3Dxx при ПЗУ 48, выход по M1 из ОЗУ), NMI (Magic).
- ОЗУ — SRAM: чтение за 1 такт 28 МГц, запись за 2 (/WE через ODDR2 на полтакта позже адреса), видео — слоты c5 % 8 = 0 (4 на знакоместо, Ф1 берёт 2), запись CPU через буфер на одно слово; в турбо 14 чтение ждёт WAIT, только если попало на слот видео.
- ПЗУ (4 страницы, `core.json` с адреса 0) — в SDRAM через `baseconf_storage` (как baseconf), CPU ждёт байт по WAIT (на 3,5 МГц ожиданий нет).
- Видео `p4096_video.v`: счётчики и адрес по схеме (VM_A0 / VM_A1 / 8/64PX), 4 слота; удвоитель `p4096_scandbl.v` хранит RGB 12 бит после палитры, кадр 896×640 / 720×576 на 28 МГц.
- Проверки (Verilator, `make sim-video` / `sim-int` / `sim-boot`): кадр стандартного режима совпадает с `p4096_vmodel.py` точка в точку; меню 128 грузится (и в турбо 14); INT: `int_test.asm` в 4 фазах HALT — первые полосы бордюра в тех же точках, что у unreal-ng PENTAGON (INT в строке 239, T 220 от начала строки h = 16, то есть 17988 T до бумаги, 32 T; unreal-ng docs/timing/pentagon-border-timing.md: фаза HALT квантует INT по 4 T, бордюр там +1 T).
- Схема HW.md: `SRA14` = gl и (`T_DOS` или `SPAGE0`) (без инверсии; проверено загрузкой).
- Плата Mini G (сборка 26112001, 5 699 LUT / 37 %, 3 RAMB16, тайминг выполнен и в режиме ядра): меню 128 на HDMI, 128 BASIC с USB-клавиатуры, `BORDER 2` (красный бордюр), `PLAY "cdefgab"` — ноты AY в левом канале HDMI-звука; после сброса с CPU 14 МГц меню снова грузится (что пункт OSD применился, не подтверждено). Найдено: в тишине звук имел сдвиг −10240 — исправлено (тишина = 0), в следующей сборке.
- Отзыв пользователя по OSD (2026-11-20): CPU, INT, Magic, Reset — ок; «INT X corr» и подписи значений пунктов не нравятся — обсудить; джойстиков два: Joystick L / Joystick R с вариантами profi / tsconf (Kempston, Sinclair1, Sinclair2, Cursor, QAOPM, QAOPS), по умолчанию L = Kempston, R = Sinclair1 (Sinclair и Cursor — через hid_parser JOY_TYPE, как в tsconf). Игры с ленты пока не проверяем.
- Плата, сборка 26112002 (5 683 LUT, тайминг выполнен в обоих режимах): тишина звука = 0 (сдвиг исправлен); Turbo 14 через OSD — `BEEP 1,0` 720 Гц / 0,36 с против 262 Гц / 1,00 с на 3,5 МГц, то есть ×2,75, а не ×4: цикл BEEP в ПЗУ, а каждый байт ПЗУ из SDRAM ждёт WAIT (кэш ПЗУ в BRAM — если понадобится «No wait», вместе с WAITP Ф3); Kempston L: `IN 31` = 17 (вправо + огонь); джойстик R «Sinclair1» даёт клавиши 1-5 (вправо «2», огонь «5»): нумерация `hid_parser` / tsconf / profi, у Fuse и Interface 2 «Sinclair 1» = 6-0 — вопрос пользователю.
- OSD Ф1 (решение пользователя 2026-11-20): Turbo (Off / 7 MHz / 14 MHz), INT (Pentagon / Pent -2T / Firm / Firm -2T: XJ3 вошёл в пункт INT), Joystick L / R (Kempston / Sinclair1 / Sinclair2 / Cursor / QAOPM / QAOPS, по умолчанию Kempston / Sinclair1; через `hid_parser`, как tsconf), Magic (F11), Reset (F12) — кадр показать до мержа.

### Ф2 — видеорежимы и палитра (ветка f2-video)

Все режимы таблицы, их сочетания по примечаниям README, FlashColor, автоматический GigaScreen, палитра 4096 (#xxFF, #F6, запись по #FF37 D5), порты #EFF7 / #FE37, режимы вывода по решению Ф0.
Цель: кадры симуляции совпадают с моделью Ф0 пиксель в пиксель на своих тестовых программах (каждый режим, переходы между режимами внутри кадра, палитра на бордюре); на плате — те же программы и найденный софт.

### Ф3 — память и порты BIOS (ветка f3-memory)

Сначала дочитать схему: статическое ОЗУ / кэш (`HLOAD`, `HRMP`, `/CC_ON`, `SRCS`, `BRCS`, DD58), страницы BIOS (`BPAGE`), запись / стирание флеш-ПЗУ (`RFLASH`, `RERASE`), #FB / #7B (`PRNROM`, `MCACHE`), многозадачность (ош. 9).

4 МБ и схемы 0-6 #FC37, D5 #7FFD, #DFFD, #1FFD, режим +3 (+3 BASIC / +3 DOS), #EFF7 D3, кэш #FB / #7B, статическое ОЗУ (загрузка #FC37 D5, подмена #FD37), #FF37 (BIOS ROM, защёлка Gluk, запись / стирание основного ПЗУ — в копию в SDRAM, до выключения), ловушка IN / OUT, многозадачность (аппаратная часть), порт 0x33.
OSD задаёт значения портов BIOS при сбросе, запись в порты работает как в оригинале. Без BIOS ядро делает то, что делал BIOS: палитра стандартными цветами, BIOS ROM выключен, переход по пункту «Сброс в» (Gluk / Menu-128 / TR-DOS / TR-DOS без очистки / BASIC 48; загрузка с HDD — после Ф4). Пункт OSD «Старт с BIOS» оставляет настоящий BIOS v4.2 (тест ОЗУ, Setup).
Цель: тесты памяти (BIOS v4.2 и свои) во всех схемах; 1024-программы под Pentagon / Профи / Scorpion / KAY; Gluk Reset Service; +3.

Части без готового софта (многозадачность: меню задач в BIOS автор только планирует) — только аппаратная часть, проверка своими программами на sjasmplus.

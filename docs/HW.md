# Pentagon-4096: разбор схемы

Источник: [AleksandrDneprCity/Pentagon-4096](https://github.com/AleksandrDneprCity/Pentagon-4096) 434fff9, `Hardware/Export/PNG/MainBoard-v10.7-sch.png` (6204×4757), `TopBoard-v5.3-sch.png`, ошибки схемы `READMY_ERRORS.md` (в разборе уже учтены и отмечены «ош. N»).
Обозначения: `/X` — активный низкий; «чек» — прочитано не до конца, проверить.

## Дешифраторы портов

`/IORQG` (DD149, DD150) = `/IORQ` или IORQGE любого слота NemoBus 1-4: внутренние порты отвечают, только если карта в слоте не взяла цикл (цепочка приоритета слотов: слот N получает IORQ, если слоты < N молчат). В ядре — приоритет внутренних устройств (GS и т.п.), внешних слотов нет. `/IOWR`, `/IORD` — запись / чтение порта.

### #xxFD (DD71 ИД7)

Входы A13 / A14 / A15 → выходы; разрешение `/IORQG` = 0, A1 = 0, A2 = 1 и M1 = 1 (DD54:4). **A0, A3-A12 не проверяются.**

| A15 A14 A13 | Выход | Порт |
|---|---|---|
| 000 | `/P_1FFD` | #1FFD |
| 001 | `/P_3FFD` | #3FFD (только для soft 7FFD) |
| 010 | `/P_5FFD` | #5FFD (то же) |
| 011 | `/P_7FFD` | #7FFD |
| 101 | (Q5) | #BFFD — AY данные |
| 110 | `/P_DFFD` | #DFFD |
| 111 | `/P_FFFD` | #FFFD — AY регистр |

AY: BDIR / BC1 из `/WR`, Q5 и `/P_FFFD` (DD74:1/2, DD70:1, DD67:6), обычная схема 128K.

### Ловушка `IN A,(n)` / `OUT (n),A` (DD72, DD68:2)

DD72 (ЛА2, 8И-НЕ) = 0, когда на шине данных `11011x11` (DB или D3; D3 не проверяется). DD68:2 (ТМ2) защёлкивает это по фронту M1 (ош. 5: тактировать `/M1` прямо с процессора, не `MM1`) → Q = 0, пока выполняется команда DB / D3 (до следующего M1).

- `/P_7FFDS` (DD76:1) = `/P_7FFD` **или** (Q = 0 и одно из `/P_1FFD`, `/P_3FFD`, `/P_5FFD`): в ловушке #7FFD отвечает на любой A15 = 0, A1 = 0 (и A2 = 1).
- `/WRHR` (DD89:1, DD74:4, DD88:2, DD89:2) = `/WR` и не (ловушка) и не ((`RAM_48` или `MTASK_ON`) и `ROM_SP`). Через `/WRHR` пишутся #7FFD D5-D7, #DFFD, #1FFD (ош. 6), +3 #1FFD. Чек: полярность `RAM_48` / `MTASK_ON` в DD89:2.

### #7FFD

- DD75 (ТМ9): D0-D2 → `7FD0-2` (страница), D3 → `FD_SCR` (экран), D4 → `SPAGE0` (ПЗУ), D5 → `7FD5B`. Такт: DD55:2 = ИЛИ(`/P_7FFDS`, `/WR`, `RAM_48`) — **мягкая** дешифрация, блокируется защёлкой.
- `RAM_48` (DD76:2) = `7FD5B` и `7FD5_BLK` (#FC37 D4): D5 работает как защёлка 48K только при #FC37 D4 = 1.
- DD77 (ТМ8): D6 → `7FD6`, D7 → `7FD7`, D5 → `7FD5` = D5 и не `7FD5_BLK` (DD69:4). Такт DD69:3 = ИЛИ-НЕ(`/P_7FFD`, `/WRHR`) — **жёсткая** дешифрация, не пишется в ловушке.
- Чтение #7FFD: DD98 (ИР22): 7FD0-2, FD_SCR, SPAGE0, 7FD5B, … (чек: старшие биты и адрес чтения).

### #DFFD (DD79 ТМ8)

D0-D2 → `DFD0-2`; такт DD78:1 = ИЛИ-НЕ(`/P_DFFD`, `/WRHR`). Остальные биты не хранятся.

### #1FFD

- DD80 (ТМ9), Scorpion / KAY: D0 → `RR_1F` (ОЗУ на место ПЗУ), D1 → `SHROM` (сервисное ПЗУ), D3 → `RA15M` (чек), D4 → `1FD4`, D7 → `1FD7`.
- DD81 (ТМ8), +3: D0 → `3+DOS`, D1 → `1FD1_3+`, D2 → `1FD2_3+`; такт DD78:2 = ИЛИ-НЕ(`/WRHR`, ИЛИ(не A12, `/P_1FFD`)) — нужен A12 = 1; сброс, пока `MODE_3+` = 0 (DD78:3, DD76:3).
- Чек: такт и сброс DD80 при `MODE_3+`.

### #xxF7 (DD90 ИД7): часы и #EFF7

Входы A12 / A13 / A14; разрешение A3 = 0, `/IORQG` = 0, A2 = 1, A6 = 1, M1 = 1 (DD51:3). **A15, A0, A1, A4, A5, A7-A11 не проверяются.**

| A14 A13 A12 | Порт |
|---|---|
| 011 | `/P_RTCBF` #BFF7 — данные часов (`RTC_DS` = чтение, `RTC_RW` = 0 при записи) |
| 101 | `/P_RTCDF` #DFF7 — адрес часов (`RTC_AS` = запись) |
| 110 | #EFF7 (запись DD93, чтение DD96) |

Часы HM6818A / 512ВИ1 (DD94) в режиме Motorola (AS / DS / R/W). Чек: участвует ли #EFF7 D7 в выборке часов (Q5 DD93 уходит к узлу у XJ1).

### #EFF7

- Запись DD93 (ТМ9), такт DD92:2 = ИЛИ-НЕ(`/WR`, Q6 DD90), сброс `/RES`:

| Бит | Цепь |
|---|---|
| D0 | `16COL_ON` |
| D1 | `512X192_ON` |
| D3 | `RR_EFF7` (ОЗУ 0 на место ПЗУ: `ROMRAM` = ИЛИ(`RR_EFF7`, `RR_1F`), DD91:4) |
| D5 | `MXCOL_ON` |
| D6 | `384X304_ON` |
| D7 | Q5 (открытие скрытых портов, чек куда) |

- Чтение DD96 (ИР22, `/OE` от DD97:1): BD0 = `16COL_ON`, BD1 = `512X192_ON`, BD5 = `MXCOL_ON`, BD6 = `384X304_ON`, BD3 = `RR_EFF7`, **BD2 = `FE_B`, BD4 = `FE_R`, BD7 = `FE_G`** (цвет бордюра #FE). D7 #EFF7 не читается.

### Порты BIOS #FC37-#FF37 (DD60 ИД7)

Входы A8 / A9 / A10; разрешение `/IOWR` = 0, A3 = A6 = A7 = 0 (DD65:1/2), A2 = 1 и M1 = 1 (DD54:3). Выходы Q4-Q7 = A10 = 1, A9 A8 = 00 / 01 / 10 / 11. **Только запись; A0, A1, A4, A5, A11-A15 не проверяются.** Регистры ИР35, сброс `/RES`.

|---|---|---|---|---|---|---|---|---|---|
| #FC37 | DD61 | `EM0_S0` | `EM0_S1` | `EM1_S0` | `EM1_S1` | `7FD5_BLK` | `HLOAD` | `MTASK_ON` | `MODE_3+` |
| #FD37 | DD62 | `HRMP0` | `HRMP1` | `HRMP2` | `HRMP3` | `HRMP4` | `HRMP5` | `HRMP6` | `HRMP7` |
| #FF37 | DD63 | `ROM_SP` | `/RSGLK` | `BPAGE0` | `BPAGE1` | `/CC_ON` | `PAL_ON` | `RFLASH` | `RERASE` |

### #FB / #7B (DD68:1)

D = A7, такт от чтения (DD69:1 = ИЛИ(`/IORD`, …), DD65:3 A2, DD30:2 = И(A1, A3, A5, A6)) → `PRNROM` / `/PRNROM`; `/S` от DD124:4 (`MCACHE`, `RES`). Чтение #FB (A7 = 1) / #7B (A7 = 0). `/P_PRNI` / `P_PRNO` — порт принтера (DD67:5, DD69:2). Чек целиком.

## Страницы памяти (DD82-DD88)

Номер страницы 16 КБ = 8 бит `MEM32K` (бит 0) … `MEM4M` (бит 7). ОЗУ = {страница, A13-A0}, 22 бита (SIMM 4 МБ).

Биты 0-2 (DD82 / DD83, выходы с третьим состоянием через 680 Ом):
- обычный режим (`3+DOS` = 0, #1FFD +3 D0): окно C000 (A14 & A15) → `7FD0-2`; остальные окна → (A14, A15, A14): 4000 → 5, 8000 → 2, 0000 → 0 (для ОЗУ на месте ПЗУ);
- +3 special (`3+DOS` = 1): S = `1FD2_3+`; 0 → {A14, A15, `1FD1_3+`} (0-3 / 4-7); 1 → {A14, A15 | (A14 & `1FD1_3+`), не (A14 & A15)} (4,5,6,3 / 4,7,6,3). Совпадает с +3.

Биты 3-7 — только окно C000 (после ош. 9 вместо `A14&A15` — `HRAM` = A14&A15 или `MTASK_ON`):

| Бит (объём) | Мультиплексор | EM = 0 | 1 Pent | 2 Profi | 3 #1FFD |
|---|---|---|---|---|---|
| 3 (256K) `MEM256K` | DD84 A, EM0 | 0 | `7FD6` | `DFD0` | `1FD4` |
| 4 (512K) `MEM512K` | DD84 B, EM0 | 0 | `7FD7` | `DFD1` | `1FD7` |
| 5 (1M) `MEM1M` | DD85, {EM1_S0 (ош. 8), EM0} | EM1_S0 = 0: 0 / `7FD5` / `DFD2` / 0; EM1_S0 = 1: 0 / 0 / `DFD2` / `7FD7` | | | |
| 6 (2M) `MEM2M` | DD86 A, EM1 | 0 | `7FD6` | `7FD6` | `1FD4` |
| 7 (4M) `MEM4M` | DD86 B, EM1 | 0 | `7FD5` | `7FD7` | `1FD7` |

Проверка по таблице #FC37 (EM1 EM0): 0 1 → Pent-1M (D6, D7, D5); 0 2 → Profi; 0 3 → #1FFD 512K; 1 3 → KAY + Pent (1FD4, 1FD7, 7FD7, 7FD6, 7FD5); 2 2 → Profi + Pent (DFD0-2, 7FD6, 7FD7); 3 2 → Profi + #1FFD (DFD0-2, 1FD4, 1FD7). Все строки сходятся.

**Расхождение с README по строкам таблицы:** Pent-1M — по схеме бит 3 страницы = `7FD6`, бит 4 = `7FD7` (как Pentagon-512 / 1024), README: «бит 7 — 256 КБ, бит 6 — 512 КБ»; KAY + Pent — по схеме 1M = `7FD7`, 2M = `7FD6`, README: «бит 6 — 1024, бит 7 — 2048»; Profi + Pent — схема и README совпадают (D6 — 2M, D7 — 4M). Берём схему, вопрос автору 4.

`SCR256K` … `SCR4M` (DD87, DD88:1) = соответствующий `MEMxx` и `MTASK_ON`: в многозадачности экран берётся из выбранного блока 128 КБ, иначе из блока 0.

## Видеоадрес (DD39-DD46, DD104-DD110)

DRAM-мультиплексоры (S0 = `/RAS`, S1 = `CPU/V`) дают одно и то же соответствие для CPU и видео. Логический адрес видео:

| Бит ОЗУ | CPU | Видео |
|---|---|---|
| A0-A4 | A0-A4 | H0-H4 (столбец знакоместа) |
| A5-A7 | A5-A7 | V3-V5 |
| A8 | A8 | `V0/6` |
| A9 | A9 | `V1/7` |
| A10 | A10 | `V2/G` |
| A11 | A11 | `V6/5V` |
| A12 | A12 | `V7/5V` |
| A13 | A13 | `VM_A0` |
| стр. бит 0 (A14) | `MEM32K` | `VM_A1` |
| стр. бит 1 (A15) | `MEM64K` | `GGSCR` (экран 5 / 7, гигаскрин) |
| стр. бит 2 (A16) | `MEM128K` | 1 |
| стр. биты 3-7 | `MEM256K` … `MEM4M` | `SCR256K` … `SCR4M` |

DD45 (S = `8/64PX`): 0 → `V0/6` = V0, `V1/7` = V1, `V2/G` = V2, `V6/5V` = V6 (адрес пикселей); 1 → V6, V7, 0, `384_A2` (адрес атрибутов: 1800 + V7-V3, H4-H0). `V7/5V` = V7 или `8/64PX` (DD25:4).

`8/64PX` = `PIX/ATTR` и не (`16COL_ON` или `MXCOL_ON`) (DD92:4, DD108:1): адрес атрибутов 8×8 только в обычных режимах; в мультиколоре и 16 colors все выборки по адресу пикселей.

Выбор `VM_A0` (DD107) и `VM_A1` / `384_A2` (DD106):
- DD107: S0 = `MXCOL_ON` | `512X192_ON` | `16COL_ON`, S1 = `512X192_ON` | `16COL_ON` | `384X304_ON`; входы 0 / `PIX/ATTR` / H5 / «3».
- DD106: S0 = (`512X192_ON` & `MXCOL_ON`) | `16COL_ON`, S1 = `16COL_ON` | `384X304_ON`; `VM_A1` ← 1 / `/PIX/ATTR` / `384_A1` / «2»; `384_A2` ← 1 / 1 / `384_A1` / 1.

Счётчик строки: F14 → F7 (пиксель 7 МГц) → CLK_3 → «2» → «3» → H0 …: одно знакоместо (8 пикселей) = 16 тактов 14 МГц, «3» и «2» делят его на 4 слота по 2 пикселя.

| Режим | Выборки на знакоместо | A13 (`VM_A0`) | стр. бит 0 (`VM_A1`) | Итог |
|---|---|---|---|---|
| Обычный | пиксели, атрибут | 0 | 1 | 4000 / 5800 страницы 5 (7) |
| Мультиколор | пиксели, атрибут (адрес пикселей) | `PIX/ATTR` | 1 | пиксели 4000, атрибуты 6000 |
| 512 моно / цветной | 4: «3» = половина | «3» | 1 | 4000 + 5800 и 6000 + 7800 |
| 512 мультиколор | 4 | «3» | `/PIX/ATTR` | пиксели 4000 / 6000 стр. 5, атрибуты C000 / E000 стр. 4 (адрес пикселей) |
| 16 colors | 4, все «пиксели» | «3» | «2» | {«3», «2»} = 00 стр. 4 C000, 01 стр. 5 4000, 10 стр. 4 E000, 11 стр. 5 6000 (порядок выборки; порядок на экране — по конвейеру, чек) |
| 384×304 | 2 | H5 | `384_A1` (`384_A2` для атрибутов) | см. раздел 384 (чек) |

«Страница 4» = блок 128 КБ экрана с битом 0 = 0: стр. 4 при `GGSCR` = 0 (экран 5) и стр. 6 при `GGSCR` = 1 (экран 7). Чек на модели.

### Пиксельный тракт (DD104, DD105)

- DD104 (S = `512X192_ON`): обычный — `F_PIX` = «3», такт сдвига `CLK_PIX` = F7, `COLOR_ON` = 1; 512 — `F_PIX` = /F7, такт F14, `COLOR_ON` = `512COL_ON` (иначе цвет из #FE37).
- DD105 (S = `16COL_ON`): обычный — `/COL_PIX` = `/PIXEL` (бит пикселя выбирает INK / PAPER), такт регистра цвета `C_COL` = `C_ATTR`; 16 colors — `/COL_PIX` = `/CLK_3` (INK / PAPER чередуются через пиксель), `C_COL` = CLK_3 (новый «атрибут» каждые 2 пикселя), `AO6/7` = AO7 вместо AO6 (яркость второго пикселя — бит 7).
- Значит, байт 16 colors = два пикселя: INK-половина (D0-D2 + D6) и PAPER-половина (D3-D5 + D7), как Pentagon 16c. Порядок левый / правый — чек по `/CLK_3`.
- `BRD_ON` = `BRD_PLACE` и не `384X304_ON` (DD88:4): в 384×304 бордюра нет.

### Автоматический GigaScreen (DD109:2, DD111:1, DD112, DD113)

- DD111:1 защёлкивает `FD_SCR` (#7FFD D3) по `KI1024S` (раз в кадр, чек момент).
- DD113:2 = `FD_SCR` xor защёлка: экран переключён программой с момента последней защёлки.
- DD113:1 = `2FRM` xor V0: чередование через строку, инверсия каждый кадр.
- `GGSCR` = (`GIGA_ON` и переключён) ? (`2FRM` xor V0) : `FD_SCR` (DD109:2, DD112:1/2/4, DD73:6). Чек полярности.
- Итог как в README: после программного переключения экрана и до следующей защёлки кадра оба экрана идут через строку; программа, которая переключает экран каждое прерывание, получает чередование весь кадр.

### Такт CPU и WAIT (DD122)

`CLK_CPU` = CLK_3 / CLK_7 / CLK_14 / CLK_14 по `/TURBO7`, `/TURBO14`; `/WAIT` (через диод) = нет / `/WAITP` / `/WAITA` / `/WAITA`. Источники `WAITP` (память в турбо 14) и `WAITA` (AY, XJ6 / XJ7) — чек.

### Цвет (DD119, DD120, FlashColor)

- Индекс цвета `MX_B/R/G/BRI` (4 бита): S0 = `/COL_PIX`, S1 = `BORDER`; INK = AO0 / AO1 / AO2 / AO6, PAPER = AO3 / AO4 / AO5 / `AO6/7` (AO6, в 16 colors AO7), бордюр = `FE_B` / `FE_R` / `FE_G` / `FE_BRI` (яркость бордюра — из #F6 D3, чек). `FBLANK` = 1 → индекс 0 (выходы КП2 выключены).
- 512 моно (`COLOR_ON` = 0): вместо регистра атрибутов на шину AO выходит регистр с `512_B/R/G` → AO0-2, `512_I` → AO6, AO3-5 = 0: текст цвета #FE37, фон чёрный.
- Пиксель: `/PIXEL` = бит пикселя xor (AO7 и (`FLASH` и не fc  или  (/F14 или F7) и fc)), fc = `FLSCOL_ON` и не `16COL_ON` (DD109:3/4, DD103:4, DD108:2/3, DD110:4, DD113:3; связи DD118:1 / DD108:3 — чек).
- `FBLANK` = fc и AO7 и не `BORDER` и пиксель = PAPER (DD57:3 + ЛИ1, чек).
- Итог FlashColor (знакоместо с битом 7): точки PAPER — чёрные; точки INK внутри точки переключаются между INK и PAPER с меандром (/F14 или F7): 1/4 периода INK, 3/4 PAPER (по вентилям; на аналоговом выходе — смешанный цвет). На HDMI — смесь цветов палитры INK / PAPER в долях 1:3 (чек на фото экрана у автора).
- `FLASH` — младший бит второго счётчика кадров (DD10?), `2FRM` — делитель кадров на 2 (для гигаскрина).

### Палитра 4096 (TopBoard: DD13, DD14, DD15-DD17 К155РУ2)

- Три ОЗУ 16×4 (канал B / R / G), адрес = текущий индекс `MX_B/R/G/BRI`: пишется тот цвет, который сейчас на выходе, поэтому писать надо во время бордюра нужного цвета.
- Запись: DD13 = A0-A7 все 1 (#xxFF), DD14 ИД7: `/IORQG` = 0, `DOS` = 0 (не TR-DOS — там #FF это порт ВГ93), `PAL_ON` = 1 (#FF37 D5), `/WR` = 0, M1 = 1 → `/WE`.
- Данные (старший бит канала первым, ЦАП 510 / 1к / 2к / 3,9к): B = D0, D5, A8, A13; R = D1, D6, A9, A14; G = D4, D7, A12, A15 — как таблица README.
- У К155РУ2 выходы инверсные (открытый коллектор, подтяжка 1к): яркость = инверсия записанного (как ATM Turbo 2+). Чек по BIOS v4.2 (стандартная палитра при старте).
- Выход через И с `BLANK`. Перемычки XJ1-XJ3 TopBoard: старый тракт 16 цветов без палитры (пункт OSD).

### Развёртка (DD5, DD6, DD8, DD11:1, DD18, DD24, DD16)

- Строка: DD5 (CT2, такт CLK_3 = 3,5 МГц) даёт «2», «3», H0, H1; DD6 — H2-H5, загрузка 2 (D1 = 1) при переносе DD5 и DD6 (DD7:1) → **H = 8..63, 56 знакомест = 448 точек 7 МГц** (Pentagon).
  - H 32..63 (H5 = 1) — бумага (адрес H0-H4), H 8..15 — правый бордюр, H 16..23 — гашение и строчный синхроимпульс, H 24..31 — левый бордюр (сходится с `video_modes.txt`: правый 6008-600F, левый 6018-601F).
  - Номер строки V растёт по фронту ИЛИ-НЕ(H3, H5) (DD12:1 → DD11:1) — в начале H = 16, в гашении.
- Кадр: V = 0..319 (320 строк): 0..191 бумага, 192..239 нижний бордюр (48), 240..255 `KI1024` — кадровый импульс (16), 256..319 верхний бордюр (64). Видимо 48 + 192 + 64 = 304 строки — экран 384×304 (у автора на форуме 2020 — «384×288», вопрос 5).
- `BRD_PLACE` = `/H5` или V8 или (V6 и V7) (DD16:2/3) — бордюр; `HC` = H5 и H3 и H2 (DD18:2: H = 44..47, 60..63).
- **Конфликт по 384×304:** на схеме `VM_A0` (A13) в этом режиме = H5 (DD107 A2, без инверсии), то есть бумага (H5 = 1) читается из 6000, бордюр из 4000; `video_modes.txt` даёт бордюр слева / справа в 6008 / 6018 (A13 = 1). Модель — по `video_modes.txt`, вопрос 5.

### Бордюр, INT, 384×304

- `BRD_PLACE` = H5 или V8 или (V6 и V7) (DD16:2/3): область бумаги — H0-H5 < 32, V < 192. `BRD_ON` = `BRD_PLACE` и не `384X304_ON`; `BORDER` — защёлка DD11:2 (задержка по `BRD_POS`).
- `384_A1` = не (V8 или V6 & V7) (DD21:6): 1 в строках бумаги.
- INT (DD24, DD20, DD22:1, DD14:3, DD17:2, DD23:2): DD24 = И-НЕ(`H-4PX`, V0, V1, V2, V3, V5, V6 & V7, XJ3) — V4 не входит, совпадает в строках V = 239 и 255. `KI1024` (DD14:3) = V4 & V5 & V6 & V7 — кадровый импульс, строки 240-255. Защёлка DD20:1 / DD20:2 (`KI1024S`): ставится по DD24 в строке 239 (точка `H-4PX`), снимается по DD22:1 (H2 & H3 & H4 & не H5) в зоне `KI1024` — чек точной строки / столбца. DD17:2 = `KI1024S` xor `INT_SEL` тактирует DD23:2: `INT_SEL` = 0 — INT по фронту `KI1024S` (Pentagon: строка 239, за ~81 строку до бумаги), `INT_SEL` = 1 — по спаду (фирменный: на 16 строк ниже и правее, по README +13,71 мкс = 96 точек). `/INT` сбрасывается по INTA (`/IORQ` и `/M1`, DD12:3) или по `HC` (DD12:4), чек длины.
- Длина INT: DD23:2 сбрасывается по INTA или по `HC` (DD12:4) — INT держится до подтверждения, но не дольше ближайшего H = 44 / 60. Точка установки `H-4PX` = «3» и H0 и H1 и H2 и … (DD9:2, DD15:1, четвёртый вход DD15:1 — по схеме не дочитан): последние 4 точки знакоместа с H0-H2 = 111.
- **Решение для Ф1:** тайминг INT берём от Pentagon-128 (README: «полная совместимость, в том числе по положению INT»): кадр 71 680 тактов, INT → бумага 17 988 тактов, длина 32 такта — по Unreal Speccy (unreal-ng `PENTAGON`); фирменный — +16 строк и +48 тактов (13,71 мкс); XJ3 — −2 такта (4 точки). Схемные значения (строка 239, `H-4PX`, сброс по `HC`) проверяем в симуляции Ф1 и вопросом 9.
- 384×304 (`video_modes.txt`, вторая, итоговая редакция: «для пикселей принудительно обнуляем V7, убираем патч A11 для атрибутов»):
  - бумага — как обычно, страница 5 (7) 4000 / 5800;
  - строки бумаги, левые и правые 8 знакомест (H5 = 1 → A13 = 1): пиксели 6008-600F / 6018-601F (+ строка как в экране), атрибуты 7808-780F / 7818-781F;
  - верх и низ (`384_A1` = 0 → страница 4): пиксели C000-C7FF и C800-C8BF … CF00-CFBF, атрибуты D800-D8FF и D900-D9BF;
  - первая редакция того же файла (D000 / D800 / D300) с этим не совпадает, а подписи «верхняя / нижняя» перепутаны — вопрос автору; модель Ф0 строим по итоговой и сверяем со схемой (`V7/5V`, `384_A2`).

## Прочие порты

### #FE / #F6 (DD147 ТМ9)

- Запись: A0 = 0, A2 = 1, A6 = 1 (DD125:3, DD145:1, DD70:3), такт DD139:4 (`/IOWR`). Остальные биты адреса, кроме A3, не проверяются.
- D0-D2 → `FE_B/R/G` (бордюр), D3 → `TPOUT` (магнитофон), D4 → `SPEAKER`.
- **`FE_BRI` (яркость бордюра) пишется не битом данных, а адресом**: в D5 регистра идёт И-НЕ(`/IODOS`, A3) (DD70:4). Запись в #F6 (A3 = 0) → яркий бордюр, в #FE (A3 = 1) → обычный. BIOS v4.2 (2F0B-2F24) пишет индексы 0-7 в #FE и 8-15 в #F6 — с этим согласны оба прочтения, вопрос автору 14. Чек: роль `/IODOS`.
- Чтение #FE — клавиатура (контроллер PS/2 и механическая на TopBoard) и магнитофон, как Pentagon-128.
- Чтение #xxFF (DD102 = A0-A7 все 1, DD103, DD101 ИР23): последний атрибут, защёлкнутый `C_COL`; на бордюре и в TR-DOS (`BORDER` или `IODOS`) регистр не выдаётся → FF. Порт атрибутов Pentagon с полной дешифрацией младшего байта.
- Чтение #7FFD (DD98, `/OE` = `/P_7FFD` или `/IORD`): D0-D2, D3 `FD_SCR`, D4 `SPAGE0`, D5 `7FD5B`, D6, D7.

### Kempston, мышь

- `/P_JYKB` (DD144:4): чтение, A5 = A7 = 0 (DD144:1), A3 = 1 и не DOS (DD70:4) → джойстик #1F (TopBoard `PJYKEYB`, чек: клавиатура PS/2 через тот же порт?).
- `/P_MOUSE` (DD146 ЛА2): чтение, A0 = A1 = A2 = 1, A5 = 0, A6 = 1, A12 = 1, A15 = 1 → Kempston mouse #FxDF (A8 / A10 выбирает регистр на TopBoard).

### TR-DOS и ВГ93

- Вход в TR-DOS (DD141, DD137:3, DD111:2): выборка M1 из 3Dxx (A8 = A10-A13 = 1, A9 = 0, A14 = A15 = 0) при ПЗУ 48 (`SPAGE0` = 1) → `T_DOS`; выход — M1 из ОЗУ (`RAMM1`).
- Порты (DD27:2, DD132:2, DD92:3): A0 = A1 = 1, M1 = 1, `/IODOS` = 0, `/IORQG` = 0; **ош. 1: добавить A2 = A3 = 1** (иначе конфликт с #EFF7 / #FF при открытых портах). DD131 ИД14 (A7, `/WR`): A7 = 0 → ВГ93 (`CSVG`, регистры по A5 / A6, ош. 2: A1 → A6 на выв. 6 ВГ93), запись A7 = 1 → системный #FF (дисковод, сторона, `SR`, `MOTOR`, `DEN` …), чтение A7 = 1 → `DRQ` → D6, `INTQ` → D7 (DD140). Ош. 3: HLD = RDY.
- `IODOS` = `T_DOS` или #EFF7 D7 (открытые скрытые порты) — чек.

### Nemo IDE (DD153-DD157)

- DD155: A1 = A2 = 0, M1 = 1, `/IORQG` = 0, не `T_DOS` → `/IDE_EBL`; DD156 по A0 / `/RD` / `/WR`: A0 = 0 — регистры IDE, A0 = 1 — старший байт (#11, регистры DD153 / DD154 ИР23). Стандартный Nemo IDE; выбор `HDD_CS0/1` по A3 / A4 — чек.

## BIOS v4.2 (дизассемблер z80dasm, `rom_42_release_2026_07_22.bin`)

- Сброс (0000-0050): `#FE37` = 07 (текст 512 белый, цвет выкл.), `#FC37` = 1A (EM0 = EM1 = 2: схема 5 Profi + Pent, D4 = 1 — D5 #7FFD защёлка; как readme BIOS «пока фиксированно Pentagon + Profi»), `#EFF7` = 82 (**512×192 моно** + D7 открыть часы) → Setup работает в 512×192: готовая тестовая картинка для Ф2. Дальше тест ОЗУ (#7FFD, результаты в CMOS через #DFF7 / #BFF7).
- Палитра (2EEE-2F31, таблица 2F34): `#FF37` = 20 (`PAL_ON`, ПЗУ BIOS), по HALT для каждого индекса 0-15 бордюр (0-7 → #FE, 8-15 → #F6) и 4 раза `OUT (C),E` с B = старший байт таблицы, C = FF. Таблица: чёрный FF / FF, синий FE / FE, красный FD / FD, зелёный EF / EF, ярко-синий DE / DE … По раскладке HW.md это B = 0101 записано → **на выходе 1010 = 10, яркий 1111 = 15**: инверсия выхода и раскладка бит подтверждены, стандартные уровни 0 / 10 / 15.
- `#FF37`: 02 / 03 / 23 / 20 и значение из настроек (0A79); страница BIOS (D2-D3) явно не меняется — 16 КБ, похоже, весь BIOS (вопрос 3).
- Строки: «Mr.Gluk, TR-DOS, Menu-128, Basic-48, 3+Bas128, 3+Hnd128, 3+DOS, 3+Bas-48, Cache, MC146818 / DS12887, AY 3-8910/12, Master / Slave» — порядок +3 страниц: 4 редактор, 5 синтаксис, 6 +3 DOS, 7 BASIC 48 (в README 6 / 7 перепутаны).

## Выбор ПЗУ и статического ОЗУ (DD49, DD51, DD52, DD53, DD56)

- Страница основного ПЗУ = {`MODE_3+`, `SRA15`, `SRA14}` (DD56 S2 = `MODE_3+`: страницы 4-7 — +3).
- DD52 (S0 = `MODE_3+`, S1 = `RFLASH`):
  - обычный режим: `SRA15` = gl и (`/T_DOS` xor `RA15M`) и не `SHROM` (DD51:2, DD17:4, DD31:6), `SRA14` = gl и (`/T_DOS` или `SPAGE0`) … (DD51:1, DD37:3) → 0 Gluk / 1 TR-DOS / 2 Menu-128 / 3 BASIC 48; #1FFD D1 (`SHROM`) — страница 0 (сервисное ПЗУ Scorpion), #1FFD D3 (`RA15M`) меняет старший бит местами (чек назначение);
  - +3 (`MODE_3+`): `SRA14` = `SPAGE0` (#7FFD D4), `SRA15` = `1FD2_3+` (#1FFD D2) — как +3;
  - запись флеш (`RFLASH`, #FF37 D6): {`RA15M`, `SPAGE0`} — любая из 4 страниц через #1FFD D3 и #7FFD D4.
- gl — защёлка сервисной страницы (DD49:1 / DD49:2, D = 1): `/RSGLK` (#FF37 D1) = 0 держит обе в сбросе → gl = 0 → страница 0 (Gluk). После записи D1 = 1 DD49:1 встаёт по M1 в окне 0000-3FFF (DD32:2 = M1 и не (A14 | A15)), затем DD49:2 (gl = 1) — по первому M1 из ОЗУ (`RAMM1`, DD32:3). Итог: после сброса работает Gluk, пока программа не перейдёт в ОЗУ; BIOS снимает блокировку записью #FF37 = 02 / 03. Без BIOS ядро ставит gl по пункту OSD «Сброс в».
- Статическое ОЗУ 128 КБ (DD53: S0 = `/CACHE_ON`, S1 = A14 | A15): в окне 0000 при эмуляции ПЗУ / кэше страница = {`SRA15`, `SRA14`} (+ `MODE_3+` = вторые 64 КБ), иначе {#7FFD D1, D0} — режим загрузки `HLOAD` в окне C000 (как README). `HRMP0-7` (#FD37) через DD56 по номеру страницы ПЗУ решает, читать ли эту страницу из статического ОЗУ. Подробно — в Ф3.

## WAIT и турбо (DD121-DD123, DD115:2)

- Переключение турбо (`/TURBO7`, `/TURBO14`) синхронизировано DD121:1/2 (такт M1, чек).
- `WAITA` (DD123, И-НЕ): обращение в турбо к медленным портам — джойстик / клавиатура (`/P_JYKB`), ВГ93 (`/P_DOS`), часы (`/P_RTCBF`, `/P_RTCDF`), мышь (`/P_MOUSE`), AY (`/P_FFFD`, по XJ6 / XJ7 AY_GI / TSFM).
- `WAITP` (DD115:2, DD125:1): запрос CPU к памяти (`CPURQ`) в турбо 14 синхронизируется по CLK_14 и ждёт свободного слота DRAM (выборки видео 2 или 4 на знакоместо) → «290 %». **Решение для Ф1:** SRAM на FPGA успевает без WAIT; в OSD «Turbo 14: Original / No wait», «Original» = WAIT при совпадении обращения CPU со слотом видео (по слотам «3» / «2»), точное правило — вопрос 10.
